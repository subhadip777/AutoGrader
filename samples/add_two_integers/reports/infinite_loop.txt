--- Usefulness & limitations of this evaluation ---
Useful for:
  1. First-pass grading of large classes
     Example: 300 submissions for a sorting assignment are compiled, tested
     and scored overnight; the instructor only reads reports whose grade is
     incomplete or flagged.
  2. Immediate feedback while students practise
     Example: A student whose sum overflows for INT_MAX + 1 gets that exact
     input, the expected output and the UBSan message within a minute, and can
     resubmit.
  3. Plagiarism and LLM-copy triage
     Example: Two submissions with renamed variables reach similarity 0.93
     against a 0.85 threshold and are flagged; the instructor checks only
     those pairs.
  4. Coding-interview and hiring screens
     Example: Candidates are ranked by correctness, edge cases and memory
     safety, with a per-metric explanation for every rejection.
Limits of this report:
  1. Tests cannot prove correctness
     Example: A program that special-cases the exact hidden inputs passes
     every test and still gets full correctness marks.
  2. LLM-written expected outputs can be wrong
     Example: The model claims the digit sum of -1234 is -10; a correct
     program printing 10 fails that test.
  3. Timing-based complexity is an estimate
     Example: An O(n log n) sort and an O(n) loop can produce the same curve
     at n <= 32000 when input reading dominates, so both are reported as O(n).
  4. Similarity misses rewritten copies and over-flags tiny programs
     Example: An LLM answer rewritten with a different loop structure scores
     0.4 and is not flagged, while two honest 6-line add-two-numbers programs
     look identical.
